# Database Migrations Guide

This guide explains how to manage database migrations using Alembic.

## Prerequisites

1. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

2. Set up your `.env` file with database credentials:
   ```bash
   cp .env.example .env
   # Edit .env with your database settings
   ```

## Migration Commands

### Create a New Migration

After making changes to SQLAlchemy models, generate a migration:

```bash
cd backend-api
alembic revision --autogenerate -m "Description of changes"
```

Example:
```bash
alembic revision --autogenerate -m "Add user and portfolio tables"
```

This will:
- Compare your models with the current database schema
- Generate a migration file in `alembic/versions/`
- Include upgrade() and downgrade() functions

### Apply Migrations

Apply all pending migrations:

```bash
alembic upgrade head
```

### Rollback Migrations

Rollback the last migration:

```bash
alembic downgrade -1
```

Rollback to a specific revision:

```bash
alembic downgrade <revision_id>
```

Rollback all migrations:

```bash
alembic downgrade base
```

### View Migration History

Show current revision:

```bash
alembic current
```

Show migration history:

```bash
alembic history
```

Show pending migrations:

```bash
alembic show head
```

## Initial Setup

For a fresh database, run this sequence:

```bash
# 1. Create initial migration
alembic revision --autogenerate -m "Initial database schema"

# 2. Review the generated migration file in alembic/versions/
# Make sure it includes all tables you expect

# 3. Apply the migration
alembic upgrade head

# 4. Verify tables were created
# Connect to your database and check the tables
```

## Migration Best Practices

1. **Always review autogenerated migrations** - Alembic may not catch all changes
2. **Test migrations in development first** - Never run untested migrations in production
3. **Keep migrations small and focused** - One migration per logical change
4. **Never edit applied migrations** - Create a new migration instead
5. **Include both upgrade and downgrade** - Always provide a way to rollback

## Common Migration Patterns

### Adding a new table

```python
def upgrade() -> None:
    op.create_table(
        'table_name',
        sa.Column('id', sa.Integer(), primary_key=True),
        sa.Column('name', sa.String(100), nullable=False),
        sa.Column('created_at', sa.DateTime(), server_default=sa.func.now()),
    )

def downgrade() -> None:
    op.drop_table('table_name')
```

### Adding a column

```python
def upgrade() -> None:
    op.add_column('table_name', sa.Column('new_column', sa.String(50)))

def downgrade() -> None:
    op.drop_column('table_name', 'new_column')
```

### Creating an index

```python
def upgrade() -> None:
    op.create_index('idx_table_column', 'table_name', ['column_name'])

def downgrade() -> None:
    op.drop_index('idx_table_column', 'table_name')
```

### Adding a foreign key

```python
def upgrade() -> None:
    op.create_foreign_key(
        'fk_table_ref', 'table_name', 'referenced_table',
        ['column_id'], ['id']
    )

def downgrade() -> None:
    op.drop_constraint('fk_table_ref', 'table_name', type_='foreignkey')
```

## Troubleshooting

### "Can't locate revision identified by..."

This means the alembic_version table is out of sync. Solutions:

1. Check current state: `alembic current`
2. Stamp to a specific revision: `alembic stamp <revision>`
3. Or reset: `alembic stamp head`

### "Multiple head revisions are present"

You have conflicting migrations. Merge them:

```bash
alembic merge heads -m "Merge migrations"
```

### Migration not detecting changes

1. Make sure models are imported in `alembic/env.py`
2. Check that your model changes are actually different from the database
3. Use manual migration if autogenerate doesn't catch it

## Production Deployment

For production deployments:

1. **Backup database** before running migrations
2. Run migrations during maintenance window if needed
3. Use transaction-safe migrations when possible
4. Test rollback procedure
5. Monitor application after migration

Example production deployment script:

```bash
#!/bin/bash
# production-migrate.sh

# Backup database
pg_dump $DB_NAME > backup_$(date +%Y%m%d_%H%M%S).sql

# Run migrations
alembic upgrade head

# Check if successful
if [ $? -eq 0 ]; then
    echo "Migration successful"
else
    echo "Migration failed - consider rollback"
    # alembic downgrade -1
fi
```

## Initial Migration (First Time Setup)

Since we already have models defined, here's how to create the initial migration:

```bash
# 1. Ensure PostgreSQL is running and database exists
# 2. Update .env with correct database credentials
# 3. Generate initial migration
alembic revision --autogenerate -m "Initial schema with users, portfolios, and optimization"

# 4. Review the generated migration file
# 5. Apply migration
alembic upgrade head
```

This will create all tables defined in:
- `app/models/user.py` - User, UserSession, UserSettings
- `app/models/portfolio.py` - Portfolio, PortfolioStock, Watchlist, WatchlistStock
- `app/models/optimization.py` - OptimizationRun, BacktestResult, StockPriceCache, FundamentalsCache
